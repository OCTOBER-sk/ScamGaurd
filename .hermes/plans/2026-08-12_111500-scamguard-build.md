# ScamGuard Build Implementation Plan

> **For Atom (supervisor):** execute via opencode agents (zeus/midas/ambush) phase-by-phase.
> Atom NEVER writes implementation code — craft prompts, dispatch, verify, commit, report.

**Goal:** Build ScamGuard — a BYOK Chrome MV3 scam-risk checker for OLX/Quikr listings + a
Message & Payment Check surface — fully implementing PLAN-BACKEND.md and PLAN-FRONTEND.md.

**Architecture:** Vanilla ES modules, zero runtime deps (jsdom + node:test are dev-only).
Heuristics-first (instant, zero network) → LLM fusion → verdict seal UI. MV3 service worker
orchestrates all provider calls. Popup-only presentation (no page-DOM injection).

**Tech stack:** JS (ES modules), JSDoc types, node:test, jsdom, Chrome MV3.

**Source-of-truth specs (repo root, referenced as `§`):**
- `PLAN-BACKEND.md` — data contracts, heuristics, providers, prompts, scoring, errors, security
- `PLAN-FRONTEND.md` — design system, popup states, options, manifest, store assets

- `prompt-engineering` — crafting each phase prompt — every phase
- `plan` — this document
- `project-security` — Phase 8 security audit
- `technical-writing` — Phase 8 README/store copy review

## Risks / Open Questions

1. **OLX live fixture capture** — OLX.in blocks this VPS's egress (curl/web_extract time out);
   Playwright chromium lacks system libs (no sudo to install). Synthetic labeled fixtures are in
   place; Sandy can drop real captures anytime via the documented §10 steps +
   `scripts/redact-fixture.js`. Extractor is defensive (extractionConfidence) either way.
2. **Gemini/DeepSeek model IDs rotate** — provider presets keep configurable defaults; Test
   connection flow handles it per §3.2/§3.6.
3. **Store policy pages change** — §7.3/§8.4 copy must be re-verified at submission time.
4. **No runtime deps is a hard constraint** — agents must not add any (canvas/JS built-ins only).
